# Setup Notes — deviations from the phase prompts made during the actual build

Anything the build did differently from the literal text of a `Phase_N` prompt is
recorded here, with the reason.

## Phase 0

### Dependency version substitutions (Python 3.14 compatibility)

The Phase 0 prompt pins `backend/requirements.txt` to versions that do **not** have
`cp314` wheels and fail to build from source on the developer's Python 3.14.5:

| Package | Prompt pin | Actual pin | Reason |
|---|---|---|---|
| `pydantic` | `2.10.4` | `2.13.5` | `2.10.4`'s `pydantic-core` has no cp314 wheel; source build fails — PyO3 0.22.6 caps at Python 3.13. `2.13.5` ships `pydantic_core-2.46.5-cp314` wheels. |
| `pydantic-settings` | `2.6.1` | `2.15.0` | Kept in lockstep with `pydantic` 2.13.x. |
| `python-dotenv` | `1.0.1` | `1.2.3` | Resolved as a `pydantic-settings` dependency; harmless newer patch line. |
| `psycopg2-binary` | `2.9.10` | `2.9.13` | `2.9.10`'s cp314 wheel installs but fails at import: `ImportError: DLL load failed while importing _psycopg`. `2.9.13` imports cleanly. |

`google-genai>=1.51.0` resolved to `2.22.0` — satisfies the hard minimum.
All other prompt pins (`fastapi==0.141.1`, `uvicorn==0.34.0`, `neo4j==6.2.0`,
`sqlalchemy==2.0.44`, `redis==5.2.1`, `pytest==8.3.4`, `pytest-asyncio==0.25.0`,
`httpx==0.28.1`) installed unchanged.

### Node.js

The machine's default `PATH` node was v16.20.2 (too old for Next.js 16). `nvm4w`
already had **v24.14.1** installed; ran `nvm use 24.14.1` (nvm4w persists this
globally). A standalone `D:\NodeJS LTS\node.exe` (v24.16.0) is also present — both
are fine. `create-next-app@latest` produced **Next.js 16.3.4 / React 19.2.8 /
Tailwind v4** (prompt said "Next.js 14+"; latest is newer).

### Frontend scaffold cleanup

`create-next-app` initializes its own nested git repo and adds `AGENTS.md` /
`CLAUDE.md`. The nested `.git` was removed (this is a single-repo monorepo). The
`AGENTS.md`/`CLAUDE.md` files are re-generated by `next dev` on every run, so they
are committed rather than fought.

### Stale Docker containers from a prior attempt (Phase 0)

Docker had leftover `pactscan-neo4j/postgres/redis` containers and `infra_*`
volumes from an earlier attempt (compose project `infra`). These held no data
relevant to a fresh Phase 0 (no schema/graph exists yet), so they were removed and
recreated cleanly under the `pactscan-dev` compose project. The known native
PostgreSQL Windows service on port 5432 was confirmed present — the container's
`5433:5432` mapping avoids it as intended.

## Phase 1

### Dependency choices / substitutions

| Package | Prompt | Actual | Reason |
|---|---|---|---|
| `reportlab` | `4.2.5` | `5.0.1` | current cp314-compatible release |
| `pytest` | `8.3.4` | `9.1.1` | pulled in by the `pytest-asyncio` bump below; suite passes clean on 9.x |
| `pytest-asyncio` | `0.25.0` | `1.4.0` | `0.25` emits ~15 `asyncio.get_event_loop_policy` DeprecationWarnings per test on Python 3.14 |
| document parsing | `llama-cloud` (`client.parsing.parse`) | `llama-cloud==2.16.0` | The prompt's `client.parsing.parse(...)` call **is** the new `llama-cloud>=1.0` API. | `python-multipart` | (not listed) | `0.0.32` | required by FastAPI for `POST /api/detect` file uploads |

### Gemini Interactions API — confirmed real

The Phase 1 prompt specifies Gemini's Interactions API (`client.interactions.create`,
`response_format`, `interaction.output_text`). This **does** exist in the installed
`google-genai==2.22.0`. `app/llm/client.py` uses:
`client.interactions.create(model=, input=, system_instruction=, response_format=TextResponseFormat(type="text", mime_type="application/json", schema_=<json schema>))`
then reads `interaction.output_text`. If live testing shows the call shape is off,
`_call_gemini()` in that one file is the only thing to adjust.

### Design choices beyond the prompt

- **`GraphStore` abstraction** (`app/agents/detect/graph_store.py`): an interface with
  `Neo4jGraphStore` (real Cypher, incl. `OVERRIDES*1..3`) and `InMemoryGraphStore`.
  The mocked test suite uses the in-memory store so it needs **no Docker/Neo4j**,
  keeping "mocked = zero env dependency" true (lessons-learned §4). Live tests and the
  running API use Neo4j.
- **Test files**: `test_detect_agent.py` (agent behaviour), `test_detect_api.py`
  (endpoint), `test_llm_client.py` (cache + fallback), `test_detect_live.py`
  (`-m live`). The prompt named only `test_detect_agent.py`.

### Cypher: `size()` not `length()` for variable-length relationship lists

`get_overriders()` first used `length(rels)` on a `-[rels:OVERRIDES*1..3]->` list —
Neo4j 5 rejects this (`length()` wants a Path). Fixed to `size(rels)`.

### LlamaParse `client.parsing.parse` call shape (fixed after first live run)

First attempt passed `output_options={"markdown": True, "include_page_breaks": True}`
and no `expand` → `ValueError: You should provide a non-empty sequence for the
'expand' parameter`. Correct call for `llama-cloud` 2.16:
`client.parsing.parse(tier=<tier>, version="latest", upload_file=file_from_path(path), expand=["markdown"])`.
Response: `result.markdown.pages` — a list of page objects with `.markdown` /
`.page_number` / `.header` (or `.error` on a failed page); fallbacks to
`result.text.pages` then `result.markdown_full` / `result.text_full`.
Parsing tier is `LLAMA_PARSE_TIER` in `.env` (default `fast` — cheapest, no AI).

### `pytest.ini`: `addopts = -m "not live"`

Plain `pytest` runs the mocked suite only; `pytest -m live` overrides addopts and
runs only the live tests. Without this, a plain `pytest` with keys present in
`.env` also ran the live tests and burned quota.
